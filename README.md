# A股每日复盘

每天 A 股收盘后自动生成一份复盘，发布成网页，手机点开就能看。

- **站点**：https://bikelife2024.github.io/a-share-daily/
- **仓库**：https://github.com/bikelife2024/a-share-daily
- **运行**：GitHub Actions，周一至周五北京时间 16:10（`cron: 10 8 * * 1-5`）
- **依赖**：纯 Python 标准库，不需要装任何包，不需要任何接口密钥

## 它每天做什么

1. 拉六个指数（上证、深证、创业板、科创50、中证1000、北证50）的收盘、涨跌幅、成交额，以及涨跌家数、涨跌停家数
2. 判断盘面性质（全面普跌 / 权重护盘 / 结构分化），并标出是否收在当日最低点
3. 拉 30 个申万一级行业的涨跌幅，分杀跌端、中间带、抗跌端；单独判断「是不是只有 AI 硬件在跌」
4. **今日资金流向**：主力 / 超大单 / 大单 / 中单 / 小单五档净额，看是「机构卖、散户接」还是反过来；再拆沪市、深市，并列出行业主力净流入流出榜
5. **异动板块**：涨跌幅两端各 5 个行业，并点出「涨幅第一但资金净流出」这种假强势
6. **异动个股**：涨停 / 跌停 / 炸板家数与炸板率、连板梯队（封单、换手、首封时间）、龙虎榜净买入榜
7. 三层传导链：海外市场 → 国内结构 → 两融杠杆
8. 位置坐标：三大指数与 MA5/20/60/120 的距离、距近期高点回撤
9. **四条锚逐条打「到位 / 未到位」**：外部锚、杠杆锚、结构锚、情绪锚，据此给防守/震荡/进攻档位
10. 下个交易日开盘观察清单

四条锚的判定口径是固定的，每天一致，所以可以直接纵向对比「昨天未到位，今天到位了」。

## 数据源与口径（重要）

| 数据 | 来源 | 口径 |
|---|---|---|
| 六大指数 | 东财 `ulist` | 交易所口径 |
| 涨跌家数 | 东财 `ulist` 的 f104/f105/f106 | 上证 + 深证综指 + 北证50 三市成分股统计相加 |
| 涨跌停家数 | 东财涨停池 / 跌停池 | 封板数 |
| 行业涨跌 | 东财板块指数（按 BK 代码批量取） | **板块内成分股等权，不是总市值加权** |
| 两融余额 | 东财 datacenter | 沪深两市合计，T-1 数据 |
| 均线 | 东财 K 线（前复权） | — |
| 五档资金流 | 东财 `fflow/kline` 分钟级 | 最后一条即全天累计；主力 = 超大单 + 大单 |
| 行业主力净额 | 东财 `ulist` 的 f62；失败时退化为逐板块 `fflow` | 只查涨跌幅两端，取不到的行业不显示 |
| 涨停 / 跌停 / 炸板 | 东财 `push2ex` 三个池子 | 涨停封单是**金额**，跌停封单是**股数** |
| 龙虎榜 | 东财 `datacenter-web` | 同一只股票多条上榜原因，只留净买入最大的一条 |

**口径提示**：行业用的是「东财板块指数」，板块内成分股等权计算。这跟按总市值加权算出来的数会有差别——最典型的是银行：四大行涨、小城商行跌的时候，等权口径会把它拉平。读板块强弱时记住这一点。

涨跌家数这条捷径经过校验：用三市指数自带的成分统计相加，得到 317 / 5300 / 32，与逐只统计全 A 的结果完全一致，但只用一次请求。

## 为什么不用「拉全 A 逐只加权」

最初的版本是拉取全 A 约 5900 只股票的市值和涨跌幅，自己按总市值加权算行业涨跌。在本地跑没问题，但在 GitHub Actions 上跑不通：

```
东方财富对云端 IP 的 clist 分页限制极严，实测每轮只能成功 3 页左右，
之后持续返回 502，60 页根本拉不完。
```

实测：间隔 1.0 秒连发 22 页，前 3 页成功，第 4 页起全部 502；改为 0.35 秒间隔，0/12 全失败；串行补拉同样无效。

而 `ulist` 接口没有这个限制（连发 8 次，8/8 成功）。所以最终方案是：**能用 ulist 批量拿的，绝不走 clist 分页**。板块按 BK 代码批量取，两次请求拿到 30 个行业，稳定。

补一句实测结论：`ulist` 本身也有配额。同一 IP 在十几分钟内连打几十次（含大量 clist），会触发整站级的断连——连不带任何资金字段的 `ulist` 请求都返回 "Remote end closed connection"。所以生成器里凡是可能失败的取数都留了降级路径，宁可少一节内容，也不让整份报告生成失败。


## 改完代码怎么发

```bash
GITHUB_TOKEN=<token> python publish_github.py --repo a-share-daily
```

脚本走 GitHub REST API（建库、传文件、开 Pages、写 Secret、触发试跑），不依赖 `git push`。

## 微信推送怎么配

仓库 Settings → Secrets and variables → Actions 里加一个即可：

- `SERVERCHAN_KEY`：Server酱的 SendKey（走 `https://sctapi.ftqq.com/<key>.send`）
- 或 `SERVERCHAN_URL`：完整 webhook 地址
- 或 `PUSHPLUS_TOKEN`：PushPlus 的 token

三个都不配也能正常出报告，只是不推微信。

## 已知限制

- **定时会晚，但不会漏**：GitHub 免费版 schedule 允许延迟 5–20 分钟，通常 16:20 前后出。
- **节假日**：脚本先查上证最新 K 线日期，不是今天就判定休市，直接跳过，不生成空报告。
- **持仓默认不显示**：仓库是 public 才能用免费 Pages，页面等于公开，所以工作流设了 `SHOW_HOLDINGS: "0"`。本地自己看时，`holdings.json` 存在就会显示。
